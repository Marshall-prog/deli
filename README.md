# Дели — счёт на всех

Статическое веб-приложение (PWA): считаем общий счёт — позиции, скидка, чаевые, доля
каждого — и отправляем друзьям ссылку, в которой уже весь расчёт.

Без регистрации, без сервера, без базы. Всё считается в браузере на устройстве.

## Как это работает

- **Создатель** заполняет позиции (что заказали, сколько, кто за это заплатил), скидку,
  чаевые и режим деления — поровну или по тому, кто заказал.
- **Ссылка** (`#b=…` в адресе) содержит весь счёт в base64url. Никакого сервера:
  ссылка просто несёт данные.
- **Друг** открывает ссылку, выбирает своё имя, видит свою долю и отмечает оплату.
  Приложение выдаёт ссылку со статусом — её нужно отправить обратно тем, кто собирает
  счёт. У того сразу появляются отметки об оплате.
- Счёт хранится в `localStorage` браузера, поэтому приложение продолжает работать
  без интернета после первого открытия.

## Файлы

```
index.html            разметка (два режима: создатель и гость)
styles.css            стили, две темы, мобильный-first
logic.js              вся математика: расчёты, округление, base64url-ссылки
app.js                слой интерфейса: DOM, localStorage, шторка со ссылкой
manifest.webmanifest  PWA-манифест (установка на главный экран)
sw.js                 service worker: офлайн-кэш статики
icons/                иконки: SVG + PNG (180/192/512 + maskable)
scripts/make_icons.py генератор PNG-иконок на чистом Python (zlib + struct)
scripts/run_tests.py  прогон тестов логики на QuickJS (dukpy)
scripts/check_ids.py  статическая проверка: id в разметке ↔ id в скрипте + синтаксис JS
tests/logic.test.js   67 проверок расчётов, ссылок и текстов
```

## Деплой (статика, бесплатно)

Вариант 1 — **Cloudflare Pages, Direct Upload** (без CLI и без git):

```bash
python3 scripts/make_dist.py   # → dist/dela-pages.zip (файлы в корне архива)
```

1. Cloudflare Dashboard → Workers & Pages → Create → Pages → Upload assets → загрузить
   `dist/dela-pages.zip`.
2. Домен вида `dela.pages.dev`.

Тот же деплой из командной строки (скрипт сам создаёт проект и проверяет сайт):

```bash
CF_API_TOKEN=… CF_ACCOUNT_ID=… python3 scripts/deploy_cf.py
```

Токен нужен с правами `Pages:Edit` + `Account:Read`; в логи он не пишется и на диск не падает.
Проверен локально только multipart-тело запроса — сам вызов API требует токена.

Вариант 2 — **GitHub Pages**: залить папку в репозиторий, Settings → Pages → deploy from
branch → root. Сайт будет на `https://<user>.github.io/<repo>/`.

Вариант 3 — **любой статический хостинг** (nginx, nginx в докере, S3+CDN): положить
папку как есть.

> Service worker (офлайн) работает только на `https://` или `localhost`.

## Формат ссылки

`https://<домен>/#b=<base64url(json)>`

В JSON: `t` — название, `p` — участники, `i` — позиции `[название, цена, кто платил]`,
`d` — скидка `[тип, значение]`, `tp` — чаевые, `s` — режим деления (`e`/`i`),
`pd` — отметки об оплате.

## Правила расчёта

- Все суммы считаются в копейках (целые числа), ошибка float не накапливается.
- Остаток от деления раздаётся по методу наибольших остатков: сумма долей всегда равна итогу.
- Скидка процентная считается от суммы позиций, фиксированная — обрезается по сумме позиций,
  итог не уходит в минус.
- Чаевые считаются от суммы после скидки.
- «Кто заплатил» = позиции, за которые этот человек заплатил, + ручные отметки.
